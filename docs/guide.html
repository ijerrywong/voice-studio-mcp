用自己的音色做有情绪的 AI 口播

2026-10-19

用开源模型 IndexTTS-2.5 把「自己的音色」和「榜样博主的情绪节奏」拼在一起，生成不再像念稿的口播；再包成一个 MCP 工具，让 Claude Code 做视频时自动配音，并拿到每个字的时间来对齐画面。

01原理

念稿感的根源是每句话都一个模板：音高起伏小、句尾不落、停顿一样长。我本人录音的音高起伏约 8 个半音，榜样博主是 15–17 个，差了一倍。方案靠三个机制解决：

① 音色 / 情绪分开音色取自自己的录音，情绪取自博主的片段
② 逐段生成 + 对齐每段生成后用 whisper 逐字对时间
③ MCP 自动调用AI 做视频时直接拿音轨和时间表
  1. 音色和情绪分开喂给模型。普通的声音克隆会把参考录音的语气一起学走，用平淡的录音克隆，出来还是平淡的。IndexTTS-2.5 有两个独立输入：spk_audio_prompt 只取音色（用自己的录音），emo_audio_prompt 只取情绪和节奏（用博主的片段），emo_alpha 调情绪强度（0–1）。
  2. 逐段生成，再逐字对齐出时间轴。稿子按镜头切成段，一段生成一个音频。IndexTTS 不输出时间信息，所以每段生成后用 whisper（开启 DTW）识别一遍，再和原稿逐字对位，得到每个字的开始和结束秒数。识别和原稿不一致的地方就是可能读错的地方，可以顺带检查。
  3. 包成 MCP 工具，让 AI 做视频时自动调用。Claude Code 做视频时调用 narrate，拿回整条音轨、每段时长和逐字时间表（timing.js），画面切换和字幕对准这些时间点。在全局 CLAUDE.md 写一句「做视频口播默认用它」，以后就是自动的。

IndexTTS-2.5 官方暂未开放「指定一句话必须几秒」的精确时长控制，只能用 duration_factor（0.5–2.0）整体调快调慢。所以思路是先生成、再测量、再让画面去适应声音，而不是让声音去凑画面。

03步骤

每一步都可以直接把这一节发给 Claude Code，让它照着做。

  1. 录一段自己的口播（3–10 分钟，正常状态），导出 WAV。让 AI 先分析一遍语速、停顿、音高起伏，确认问题在哪。我们一开始以为是普通话问题，其实是情绪和节奏。
  2. 剪音色参考：从录音里挑 1–2 句读得最清楚的，合计 10–15 秒，转成单声道 WAV。
  3. 安装 IndexTTS-2.5：git clone https://github.com/index-tts/index-tts，进目录后执行 uv sync（不要加 --all-extras，Mac 上 DeepSpeed 装不上）。
  4. 下载权重：国内用 ModelScope：uvx --from modelscope modelscope download --model IndexTeam/IndexTTS-2.5 --local_dir checkpoints。首次运行时还会自动下载约 4GB 的辅助模型。
  5. 先跑一个基准版：只给音色参考、不给情绪参考，生成一句话，确认音色像自己。这一版预计还是平的，正常。
  6. 准备情绪参考：下载榜样博主的一期视频，提取音频，用 Demucs 分离人声去掉背景音乐（demucs --two-stems=vocals），在停顿处剪出 2–3 段 10–15 秒、风格不同的片段（比如开场抛问题、利落讲解、连贯顺讲）。
  7. 做对比试听：同一段稿子，每种情绪各生成一遍，再把喜欢的那种按 emo_alpha 0.5 / 0.65 / 0.8 各生成一遍，放在一个试听页里听。两个问题：还像不像自己？还像不像念书？
  8. 写 MCP 服务：让 Claude Code 照「原理」里的三个机制写一个 Python MCP 服务。我们的工具清单：narrate（逐段生成，输出 narration.wav、timing.js、.srt）、job_status（生成慢，用任务号轮询）、retime（重做某段并逼近目标时长）、audition、save_preset、list_presets。
  9. 注册并设默认：claude mcp add -s user voice-studio -e VS_PRELOAD=0 -- <venv 里的 python> <服务脚本>；把选定的组合存成默认预设；在 ~/.claude/CLAUDE.md 加一句「做视频需要口播时，默认用 voice-studio 的 narrate」。新开会话生效。

04实测效果

情绪强度 0.5 最像本人，起伏从 9 个半音涨到 11 个，语速也更紧凑。代价是：强度越高，基础音高越往博主靠，听起来越不像自己。

05踩过的坑和注意事项

  • HuggingFace 大文件下载卡住：国内改用 ModelScope，约 7MB/s。
  • MCP 库版本：直接装会拿到 mcp 2.x，FastMCP 已改名，旧代码会报错。装 mcp>=1.10,<2。
  • 重跑 uv sync 会删掉额外装的包（mcp、soundfile），要重新装。
  • stdout 被污染：IndexTTS 会往标准输出打印日志，而 stdio MCP 用标准输出通信。启动时要把文件描述符 1 改指 stderr，MCP 用复制出来的原 stdout。
  • 工作目录：IndexTTS 导入时把缓存目录写成了相对路径。服务启动时切一次目录就固定下来，不要在运行中反复 chdir，否则并发时路径会乱。
  • whisper 时间戳不准：不开 DTW 时开头能偏 1 秒。要加 -dtw large.v3.turbo -nfa，再用能量检测的口播起止做首尾校准。
  • 不要预加载模型：用户级 MCP 每个 Claude 会话都会启动一份，预加载会让每个会话白占约 4GB 内存。改成第一次调用时才加载，多等约 20 秒。
  • 英文词要试听：如 CAD、产品名，可能读法不对。
  • 速度：Mac 上 CPU 和 MPS 一样快，改 beam 数提升有限。有 NVIDIA 显卡会快很多。
  • 授权：只克隆自己的声音。博主片段只用作本地情绪参考，不要随项目公开。IndexTTS 用的是 bilibili 模型许可，个人和中小团队可以免费使用；月活超过 1 亿或年收入超过门槛的要另外申请。
